# Publication manifest -- DECISIONS 34.
#
# Publication is by file copy into a fresh public repository, never by pushing
# this history and never by rewriting it. This file is the list of what gets
# copied. One path or one directory per line; a directory means every tracked
# file under it. Blank lines and `#` comments are ignored.
#
# `internal/tests/test_docs.py` reads this file and refuses if:
#   - an entry names nothing tracked,
#   - a tracked file is neither listed here nor listed under NOT-PUBLISHED,
#   - a listed file carries vocabulary that appears in `assets/` and nowhere
#     else on this list.
#
# The third check is why the list is explicit rather than "everything except".
# The repository itself is never published, so scanning it at large would be
# scanning the wrong thing; what needs scanning is exactly what leaves.
#
# WHAT THE THIRD CHECK WILL NOT CATCH. Read this before trusting it, because
# the limits of a scan are the part the person running it most needs.
#
#   - It flags a token only when that token appears in AT MOST ONE published
#     file. Paste the same asset vocabulary into two files on this list and the
#     scan goes quiet: two occurrences look like ordinary shared vocabulary
#     rather than a leak. It was built for a single accidental paste, which is
#     the failure that actually happened here, and it is not a defence against
#     a phrase that has spread.
#
#   - It flags a token only when that token occurs at least 8 times across
#     `assets/`. A name mentioned once or twice in the source documents is
#     below the threshold and will not be seen. Eight is the lowest value that
#     leaves this manifest clean; lowering it costs false positives on ordinary
#     English, so the floor is a trade, not a safety margin.
#
#   - `tests/scan_dependencies.py` finds a read by walking literal path chains
#     in the AST. A path routed through a constant -- `SPEC = paths.BENCH_SPEC`
#     -- is invisible to it, because the path never appears as a literal. A
#     refactor therefore changes what that check covers without changing the
#     check. Only moving paths go through `repo_paths` for this reason (337).
#
#   - `assets/` is untracked. On a machine that does not have it the scan
#     examines nothing at all. It says so rather than passing quietly, but a
#     pass on such a machine is not evidence.
#
# The consequence for whoever assembles the upload: a green run of
# `internal/tests/test_docs.py` means no single-file paste of high-frequency asset
# vocabulary was found. It does not mean the copy is clean. Read the diff.
#
# --------------------------------------------------------------------------
# THE ONE JOB LEFT BEFORE THE FIRST UPLOAD. Do this as a single block, and do
# it once the corpus has stopped moving, which is the point of scheduling it
# rather than doing it now.
#
# The AT MOST ONE clause above has a measured hole. A token pasted into two
# published files is invisible to the scan, and closing the hole means raising
# that clause until the scan flags a token that is spread across many files.
# Raising it also flags the project's own ordinary vocabulary, and each of
# those needs an allowlist entry with a reason. That cost was measured over
# 53 hot tokens and 682 published files:
#
#     clause              allowlist entries needed
#     spread <= 2         0        <- today's rule, restated
#     spread <= 3         1
#     spread <= 6         3
#     spread <= 20        5
#     any spread          43
#
# Two things follow from the shape of that table, and both are why the hole is
# still open. The spread histogram has NOTHING in the 1-2 file band: 10 tokens
# appear in no published file at all, none in one or two, 5 in three to twenty,
# and the remaining 38 in twenty-one or more. So raising the clause from 2 to 3
# or to 6 buys nothing the current rule does not already catch -- there is no
# token sitting in the gap it would close. Only `any spread` closes the hole,
# and that is 43 entries.
#
# The decision: write those 43 entries, in one scheduled block, immediately
# before the first publication and not before. Each entry needs a reason, and a
# reason is only writable once the token's use is settled; entries written
# against a moving corpus rot into a stale allowlist, which is worse than no
# allowlist because it reads like one that was checked. The check that fails
# on an unused entry exists for exactly that decay.
#
# Whoever runs it: the table above is the measurement, so it does not need
# repeating. Set the clause to `any spread`, run `internal/tests/test_docs.py`, and
# write a reason for each of the 43 tokens it names.
# --------------------------------------------------------------------------
